# Important Concepts

Этот файл будет пополняться по мере прохождения курса.
Сюда будем складывать краткие, но важные наблюдения, которые часто экономят часы отладки.

## 1. Переменная — это ссылка на объект

В Python имя переменной не "хранит значение внутри себя", а ссылается на объект.
Это особенно важно для изменяемых структур данных.

## 2. Mutable vs immutable

- неизменяемые: `int`, `float`, `str`, `tuple`, `bool`
- изменяемые: `list`, `dict`, `set`

Если две переменные ссылаются на один изменяемый объект,
изменение через одну ссылку будет видно через другую.

## 3. `is` и `==` — не одно и то же

- `==` сравнивает значения
- `is` сравнивает идентичность объектов

Практическое правило:

- значения сравниваем через `==`
- `None` проверяем через `is None`

## 4. Не затеняй встроенные имена

Не называй переменные так:

```python
list = [1, 2, 3]
str = "hello"
sum = 10
```

Иначе позже встроенные функции с такими именами перестанут работать ожидаемо.

## 5. Форматирование чисел через `.2f`

Когда видишь запись вида:

```python
f"{value:.2f}"
```

это означает:

- `value` — переменная, которую нужно вставить в строку
- `:` — начало инструкции по форматированию
- `.2f` — показать число как `float` с двумя знаками после точки

Пример:

```python
value = 12
print(f"{value:.2f}")
```

Результат:

```python
12.00
```

Ещё пример:

```python
price = 1899.9
print(f"{price:.2f}")
```

Результат:

```python
1899.90
```

Это особенно полезно для денег, потому что суммы обычно хотят видеть в одном формате:

- `120`
- `120.5`
- `120.567`

после форматирования станут:

- `120.00`
- `120.50`
- `120.57`

Важно:

- `.2f` не меняет само число в переменной, а только форматирует его для вывода
- результат внутри `f-string` становится строкой

## 6. Что такое кортеж (`tuple`)

Кортеж — это структура данных, которая хранит несколько значений в одном объекте.

Пример:

```python
user_data = (104, "Elena Petrova", "premium", True)
```

Внутри кортежа могут лежать данные разных типов:

- число
- строка
- логическое значение

Главная особенность кортежа:

- `tuple` неизменяемый

Это значит, что после создания кортежа его нельзя менять поэлементно:

```python
user_data = (104, "Elena", "premium")
# user_data[0] = 200   # так нельзя
```

Когда кортеж удобен:

- данные нужно просто хранить и передать дальше;
- порядок элементов важен;
- набор значений не должен случайно измениться.

## 7. Распаковка кортежа

Очень часто кортеж сразу раскладывают по переменным:

```python
user_id, user_name, plan, is_active = user_data
```

Это называется распаковка.

Теперь:

- `user_id` будет `104`
- `user_name` будет `"Elena Petrova"`
- `plan` будет `"premium"`
- `is_active` будет `True`

Это особенно удобно, когда ты точно знаешь порядок данных.

## 8. Как это связано с задачей `Variables_06`

В задаче:

```python
user_data = (104, "  elena petrova ", "premium", True)
```

Можно сделать так:

```python
user_id, raw_user_name, plan, is_active = user_data
user_name = raw_user_name.strip().title()

summary = f"ID: {user_id} | User: {user_name} | Plan: {plan} | Active: {is_active}"
print(summary)
```

Почему это хороший подход:

- сначала мы распаковали данные;
- потом отдельно обработали имя;
- затем собрали итоговую строку.

Это читается проще, чем обращаться к элементам по индексам вроде `user_data[0]`, `user_data[1]`.

## 9. Почему `and` и `or` возвращают не только `True` или `False`

Если операнды — это обычные значения, а не только булевы переменные,
`and` и `or` возвращают один из самих операндов.

Практическое правило:

- `a or b` возвращает первое truthy-значение
- если все значения falsy, `or` возвращает последнее
- `a and b` возвращает первое falsy-значение
- если все значения truthy, `and` возвращает последнее

Примеры:

```python
print("" or "Guest")         # Guest
print("Alex" or "Guest")     # Alex
print(0 or 100)              # 100
print(15 or 100)             # 15

print("" and "Admin")        # ""
print("Alex" and "Admin")    # Admin
print(0 and 100)             # 0
print(15 and 100)            # 100
```

Почему так происходит:

- для `or` Python ищет первое "подходящее" значение
- для `and` Python ищет первое значение, на котором выражение ломается

## 10. Реальные примеры использования `or`

### Значение по умолчанию

Очень частый паттерн:

```python
display_name = user_name or "Guest"
```

Что происходит:

- если `user_name` непустой, в `display_name` попадёт он
- если `user_name` пустой, попадёт `"Guest"`

Ещё более практичный вариант:

```python
display_name = nickname or full_name or email or "Guest"
```

Python пойдёт слева направо и возьмёт первое truthy-значение.

### Конфиг и переменные окружения

```python
host = env_host or "127.0.0.1"
```

Если `env_host` пустой или `None`, будет использован запасной адрес.

## 11. Реальные примеры использования `and`

### Безопасная обработка значения

```python
clean_name = raw_name and raw_name.strip().title()
```

Что происходит:

- если `raw_name` пустой или `None`, выражение сразу вернёт это значение
- если `raw_name` есть, выполнится `strip().title()`

### Выполнить вторую часть только если первая истинна

```python
is_allowed = is_authenticated and is_verified
```

Если `is_authenticated` равно `False`, Python даже не будет дальше "разворачивать" выражение.

## 12. Почему это удобно в практике

Эти операторы помогают писать компактный код:

```python
avatar_url = uploaded_avatar_url or default_avatar_url
```

```python
final_email = primary_email or backup_email
```

```python
can_publish = is_editor and not is_blocked
```

Такой код часто встречается:

- в веб-разработке
- при обработке форм
- в конфигурации приложения
- при выборе fallback-значений

## 13. Важная ловушка

Этот приём удобен не всегда.

Проблема возникает, если falsy-значение само по себе валидно.

Пример:

```python
age = 0
display_age = age or "unknown"
```

Результат будет:

```python
"unknown"
```

Хотя `0` здесь может быть корректным значением.

То же самое касается:

- `0`
- `0.0`
- `""`
- `[]`
- `False`

Поэтому правило такое:

- используй `or` для fallback только если falsy-значения действительно означают "нет данных"
- если `0` или пустая строка допустимы, лучше писать явную проверку

Пример более безопасной проверки:

```python
display_age = "unknown" if age is None else age
```

## 14. Что такое fallback

`Fallback` — это запасной вариант, который используется,
если основное значение отсутствует, пустое или недоступно.

Проще говоря:

- есть основной вариант;
- если он не сработал, берём резервный.

Примеры из практики:

```python
display_name = nickname or "Guest"
```

Если `nickname` пустой, будет использовано `"Guest"`.

```python
avatar_url = uploaded_avatar_url or default_avatar_url
```

Если пользователь не загрузил аватар, покажем стандартный.

```python
host = env_host or "127.0.0.1"
```

Если переменная окружения не задана, используем адрес по умолчанию.

Почему это удобно:

- программа не падает из-за отсутствующих данных;
- у интерфейса всегда есть что показать;
- конфигурация приложения остаётся предсказуемой.

Но важно помнить:

`or`-fallback подходит только тогда, когда falsy-значение действительно означает
"данных нет".

Проблемный пример:

```python
discount = 0
final_discount = discount or 10
```

Результат будет `10`, хотя `0` может быть корректной скидкой.

В таких случаях лучше проверять явно:

```python
final_discount = 10 if discount is None else discount
```

## 15. Короткая шпаргалка по условиям

### 1. Сравнивай значения через `==`, а не через `is`

```python
if status == "paid":
    ...
```

`is` обычно нужен только для `None`:

```python
if value is None:
    ...
```

### 2. Нормализуй строки перед сравнением

```python
role = role.strip().lower()

if role == "admin":
    ...
```

### 3. В `if` ставь самые специфичные условия раньше

```python
if score >= 90:
    ...
elif score >= 75:
    ...
```

Иначе часть веток может никогда не выполниться.

### 4. Используй `or` для fallback только там, где falsy значит "нет данных"

```python
display_name = nickname or "Guest"
```

Но не так:

```python
price = custom_price or 100
```

если `0` — допустимая цена.

### 5. Не усложняй условие ради краткости

Если условие тяжело читать, лучше разнести его на части:

```python
is_adult = age >= 18
has_access = is_adult and has_ticket
```

### 6. Если логика важная, лучше явный `if`, чем хитрое выражение

Для доступа, денег, статусов и бизнес-правил чаще полезнее написать:

```python
if user is None:
    result = "Guest"
else:
    result = user.name
```

чем слишком умную короткую запись, которая может скрыть ошибку.

## 16. `range()` и `enumerate()` — полезные паттерны за пределами базы

### `range(start, stop, step)`

`range()` умеет не только `range(5)`.

Примеры:

```python
for minute in range(0, 60, 15):
    print(minute)
```

Это удобно для шагов:

- каждые 5 минут
- каждые 10 записей
- каждый второй элемент

### Обход по индексам кусками

```python
items = ["a", "b", "c", "d", "e", "f"]
chunk_size = 2

for start in range(0, len(items), chunk_size):
    chunk = items[start:start + chunk_size]
    print(chunk)
```

Такой паттерн встречается в:

- пагинации
- батч-обработке
- разбиении данных на блоки

### Сравнение соседних элементов

```python
temperatures = [18, 20, 19, 22]

for index in range(len(temperatures) - 1):
    current_value = temperatures[index]
    next_value = temperatures[index + 1]
    print(current_value, next_value)
```

Это полезно, когда нужно:

- искать рост или падение;
- сравнивать текущий и следующий статус;
- находить резкие изменения.

### Обход с конца

```python
for index in range(len(items) - 1, -1, -1):
    print(index, items[index])
```

Такой приём нужен редко, но полезен,
когда действительно важен индекс и движение назад.

### `enumerate()` для нумерации и диагностики

```python
lines = ["ok", "ok", "error", "ok"]

for line_number, line in enumerate(lines, start=1):
    if line == "error":
        print(f"Ошибка в строке {line_number}")
```

Это очень реальный паттерн:

- нумерация пунктов в интерфейсе;
- номер строки в файле;
- позиция ошибочного элемента;
- человекочитаемые отчёты.

Практическое правило:

- если нужен только элемент — используй обычный `for item in items`
- если нужен и номер, и элемент — используй `enumerate`
- если нужен именно индекс для соседних элементов или срезов — используй `range`

## 17. `break` и `continue` — это не только про читаемость

Да, они влияют на читаемость кода. Но не только.

### `break` влияет на логику

`break` завершает цикл полностью.

Пример:

```python
statuses = ["ok", "ok", "fatal", "ok"]

for status in statuses:
    if status == "fatal":
        print("Останавливаем обработку")
        break
```

После `break` оставшиеся элементы уже не будут обработаны вообще.

Это влияет на:

- корректность результата;
- количество выполненной работы;
- итоговое состояние переменных.

### `continue` пропускает часть шага

```python
values = [10, None, 20]
total = 0

for value in values:
    if value is None:
        continue
    total += value
```

Здесь `continue` не просто "делает код короче".
Он реально отменяет всё, что ниже него в текущей итерации.

### Где легко ошибиться

```python
values = [10, None, 20]
count = 0

for value in values:
    if value is None:
        continue
    count += 1
```

Здесь всё правильно, если `count` должен считать только валидные значения.
Но если ты хотел считать все элементы, то `continue` уже изменил смысл программы.

### `break` влияет и на производительность

Если задача — найти первый подходящий элемент,
`break` позволяет не проходить весь список до конца.

```python
for user in users:
    if user.id == target_id:
        found_user = user
        break
```

Это важно не только для чтения, но и для скорости.

### Практическое правило

- `break` — когда после нужного результата остальная работа уже не нужна
- `continue` — когда текущий элемент надо пропустить, но цикл должен жить дальше

## 18. Что такое сложность алгоритма на текущем уровне

Сложность алгоритма — это способ понять,
как растёт время работы или объём памяти при росте входных данных.

Пока нам достаточно самой базовой идеи:

- маленькие данные могут работать быстро почти при любом коде;
- на больших данных разница в подходе становится очень заметной.

### `O(1)` — постоянное время

Операция не зависит от размера данных:

```python
first_item = items[0]
```

Взять первый элемент списка — это условно постоянная операция.

### `O(n)` — один проход по данным

```python
total = 0

for value in values:
    total += value
```

Если элементов в 10 раз больше, работы тоже примерно в 10 раз больше.

Это очень частый и нормальный уровень сложности.

### `O(n^2)` — вложенные циклы

```python
for a in values:
    for b in values:
        print(a, b)
```

Если данных стало в 10 раз больше,
работы станет уже примерно в 100 раз больше.

Вот почему вложенные циклы требуют внимания.

### Где это уже влияет на практике

1. Поиск первого подходящего элемента:

```python
for item in items:
    if item == target:
        found = item
        break
```

Это обычно `O(n)` в худшем случае.
Но с `break` лучший случай может быть почти мгновенным.

2. Повторный проход внутри другого цикла:

```python
for user in users:
    for order in orders:
        ...
```

Такой код быстро дорожает по времени.

3. Лишние повторные вычисления:

Если можно пройти список один раз и всё посчитать сразу,
часто это лучше, чем проходить его много раз по разным причинам.

### Что важно запомнить сейчас

- один цикл — обычно нормально;
- вложенные циклы — уже повод задуматься;
- `break` иногда экономит много работы;
- простота и читаемость важны, но на больших объёмах данных структура алгоритма тоже начинает иметь значение.
